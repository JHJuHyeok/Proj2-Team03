# 비정형 스킬 렌더링 연구 보고서

## 1. 문제 정의

### 1.1 현재 문제
- **직사각형 모양 (1x1, 2x1, 1x2, 2x2)**: 정상 작동
- **비정형 모양 (L자 3칸, T자 4칸)**: 경계 상자(Bounding Box) 크기로 표시되어 빈 칸까지 채워져 보임

### 1.2 예시
```
L자 스킬 (실제 3칸):      현재 표시 (4칸):
■ ■                       ■ ■
■                         ■ ■  ← 빈 칸도 표시됨
```

### 1.3 원인 분석
`SkillShapeData.cs`에서 L자 모양 정의:
```csharp
SkillShapeType.L_Shape => new SkillShapeData
{
    shapeType = type,
    baseSize = new Vector2Int(2, 2),  // 경계 상자 크기
    cellCount = 3                      // 실제 점유 셀 수
},
```

`UpdateVisualSize()`는 `baseSize`를 사용하여 크기 계산:
```csharp
rectTransform.sizeDelta = new Vector2(size.x * cellSize, size.y * cellSize);
// size = (2, 2) → 2x2 정사각형으로 표시
```

## 2. 기술적 해결책 분석

### 2.1 방법 A: 개별 셀 이미지 방식 (Per-Cell Sprite)

**개념**: 아이템을 각 그리드 셀에 해당하는 개별 이미지로 분리하여 렌더링

**구현 방법**:
```
L자 아이템 구조:
┌───┬───┐
│Cell│   │  → Cell_0_0 (이미지 있음)
├───┼───┤
│Cell│Cell│  → Cell_1_0, Cell_1_1 (이미지 있음)
└───┴───┘
```

**장점**:
- 그리드 시스템과 자연스럽게 통합
- 셀 단위 하이라이트/선택 효과 용이
- 드래그 앤 드롭 구현이 직관적

**단점**:
- 각 아이템마다 여러 스프라이트 조각 필요
- 아티스트 작업량 증가
- 구현 복잡도 중간

**이전 시도 결과**:
- 구현했으나 Canvas anchor 설정 문제로 전체 화면이 색상으로 칠해지는 버그 발생
- 롤백 후 재검토 필요

---

### 2.2 방법 B: 투명 스프라이트 + 알파 마스크 방식 ★권장

**개념**: 전체 아이템을 하나의 스프라이트로 만들되, 빈 영역은 완전 투명하게 처리

**구현 방법**:
```
L자 아이템 스프라이트 (2x2 크기):
┌─────────────┬─────────────┐
│   ████      │             │
│   ████      │  (투명)     │
│   ████      │             │
├─────────────┼─────────────┤
│   ████      │   ████      │
│   ████      │   ████      │
│   ████      │   ████      │
└─────────────┴─────────────┘
```

**장점**:
- 구현이 가장 간단 (코드 변경 불필요)
- 아티스트가 원하는 형태를 정확히 표현 가능
- 기존 스킬 아이콘 제작 방식과 유사

**단점**:
- 빈 영역에서도 클릭 이벤트 발생 가능 (Raycast Target 관리 필요)
- 투명 영역이 크면 메모리 낭비

**구현 복잡도**: 낮음 (1/5)

---

### 2.3 방법 C: Unity SpriteMask 방식

**개념**: Unity의 SpriteMask 컴포넌트를 사용하여 아이템의 실제 형태만 표시

**구현 방법**:
1. SpriteMask 컴포넌트로 형태 정의
2. 아이템 이미지에 Mask Interaction 설정

**장점**:
- Unity 내장 기능 활용
- 부드러운 가장자리 처리 가능

**단점**:
- UI 시스템보다는 2D Sprite 시스템에 최적화
- 다중 아이템 간 마스크 충돌 가능성
- Sorting Layer 관리 필요

**구현 복잡도**: 중간 (3/5)

---

### 2.4 방법 D: Stencil Buffer 방식

**개념**: 커스텀 셰이더로 Stencil Buffer를 활용한 마스킹

**장점**:
- 매우 정교한 마스킹 가능
- 성능 최적화 용이

**단점**:
- 커스텀 셰이더 작성 필요
- 디버깅이 어려움
- UI 시스템과의 호환성 고려 필요

**구현 복잡도**: 높음 (4/5)

---

### 2.5 방법 E: 9-Slice + 커스텀 형태 방식

**개념**: 아이템을 여러 부분으로 나누어 동적으로 조립

**장점**:
- 모듈화된 아이템 제작 가능
- 부분별 애니메이션 적용 용이

**단점**:
- 초기 설정 복잡
- 파트 간 연결 부위 처리 필요

**구현 복잡도**: 높음 (4/5)

---

### 2.6 방법 F: 단일 스프라이트 + 형태 데이터 분리 방식 ★권장

**개념**: 하나의 스프라이트를 사용하되, 실제 점유 셀 정보를 별도로 관리

**현재 시스템과의 호환성**:
- 이미 `SkillShapeData.GetOccupiedCells()`로 점유 셀 정보 관리 중
- 그리드 배치 검증은 형태 데이터 기반으로 이미 작동 중
- 시각적 표시만 투명 스프라이트로 해결하면 됨

**장점**:
- 기존 코드 변경 최소화
- 아티스트 작업 간단 (투명 PNG만 준비)
- 드래그/배치 로직은 이미 구현됨

**단점**:
- 클릭 영역과 시각 영역 불일치 가능성
- Raycast 처리에 주의 필요

**구현 복잡도**: 낮음~중간 (2/5)

## 4. 최종 권장 해결책

### 4.1 1차 권장: 방법 F + B 조합

**이유**:
1. **구현 복잡도가 낮음**: 기존 코드를 크게 변경할 필요 없음
2. **아티스트 작업 최소화**: 투명 영역이 있는 스프라이트만 준비하면 됨
3. **유지보수 용이**: 형태 데이터와 시각 데이터가 분리되어 있어 수정이 쉬움

### 4.2 구현 단계

**Step 1: 스킬 아이콘 스프라이트 제작**
- L자 모양: 2x2 캔버스에 L자 형태로 그리고 나머지는 투명
- T자 모양: 3x2 캔버스에 T자 형태로 그리고 나머지는 투명

**Step 2: 스프라이트 설정**
- Texture Type: Sprite (2D and UI)
- Alpha Is Transparency: 체크
- Mesh Type: Full Rect (또는 Tight)

**Step 3: Raycast 설정 (선택)**
- 투명 영역 클릭 방지를 위해 `Image.alphaHitTestMinimumThreshold = 0.5f` 설정
- 또는 커스텀 Raycast 구현

### 4.3 2차 권장: 방법 A (개별 셀 이미지)

더 정교한 제어가 필요한 경우:
- 각 스킬 형태에 맞는 셀 조각 스프라이트 제작
- 셀 단위로 하이라이트/애니메이션 적용 가능
- 이전 구현 시도의 버그 수정 후 재적용

## 5. 백팩 히어로 분석

### 5.1 백팩 히어로 렌더링 방식

백팩 히어로는 다음과 같은 방식을 사용:

1. **개별 스프라이트 방식**: 각 아이템마다 실제 형태에 맞는 커스텀 스프라이트 제작
2. **투명 영역 활용**: 스프라이트의 빈 영역은 완전 투명(alpha=0)으로 처리
3. **픽셀 아트 스타일**: 명확한 경계로 인해 형태 구분이 쉬움

### 5.2 적용 가능한 점

- 투명 스프라이트 방식은 백팩 히어로와 동일한 접근법
- 형태 데이터와 시각 데이터 분리는 이미 구현되어 있음
